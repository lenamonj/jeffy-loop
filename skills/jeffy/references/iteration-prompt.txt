Read PLAN.md and BACKLOG.md in full and the last 3 entries of JOURNAL.md. Salvage first: when the project is a git repository and the working tree is dirty at the start of this iteration, the previous iteration was interrupted or a human edited mid-flight; commit everything with the message jeffy: salvage before iter i, record a SALVAGE journal entry, and continue; never reset or discard work. Ratchet next: if the latest Converged line in BACKLOG.md names a commit hash, BACKLOG.md lists no open task in Now, Next, or Later, this run carries no focus directive, and every path changed since that hash, per git status --porcelain and git diff --name-only against it, is only PLAN.md, BACKLOG.md, JOURNAL.md, or JOURNAL-archive.md, append a RATCHET journal entry recording that verification and end the run converged per the closing rule below; a seeded backlog, a focus directive, or any other changed path means the ratchet does not apply and the run proceeds normally. If the Operating envelope table in PLAN.md is unfilled, enumerate the project's real input surfaces and fill it before filing any finding; if the Verify command in PLAN.md is unfilled, fill it during the first audit with the project's real gate, or none with a one-line reason. If the Surface inventory in PLAN.md is unfilled, fill it during the first audit before filing any finding: one checkbox row per public module or entry-point group until the whole public surface is listed, then probe every row at least shallowly before any deep dive, so the worst defect in the project appears in the first filing rather than the sixth; a row flips to [x] only with the commit hash it was swept at and one line naming what the sweep exercised, and a row whose implementing code changed after its recorded commit is stale and flips back to [ ]. If BACKLOG.md has no open tasks, generate them: in Improvement mode audit the project per the Method and Operating envelope in PLAN.md, sweeping unswept or stale Surface inventory rows first and updating each row with the commit swept at - sweeping a surface that computes values requires a known-answer or invariant check per function family, never only run-without-crash probes, because wrong numbers returned without complaint survive every liveness probe - a dimension scored None claims only the rows actually swept, never the unexamined remainder, and an audit that leaves rows unswept must say so in its scores line rather than present them as the whole project - in Scoped mode derive remaining tasks from the Definition of done; write them worst severity first as one-line items with an acceptance check each, append an AUDIT journal entry with the scores, run the end-of-iteration steps, and end the turn. Otherwise execute exactly one task, the top unblocked item, never batch; when this is the final iteration, i equals N, prefer a WRAPUP entry that tidies BACKLOG.md and writes a handoff over starting a task that cannot finish. Verify the task's acceptance check, at most 3 fix attempts, else mark it [b] with a one line reason. Verify gate: after the acceptance check, run the Verify command from PLAN.md unless it is none; if it fails and it passed at the last checkpoint, this iteration broke the project: when the project is a git repository revert the working tree to the last jeffy checkpoint, mark the task [b] with the failure output, and record it in the journal entry; without git there is no checkpoint to revert to, so undo this iteration's edits directly, mark the task [b], and record it. One exception: when the newly red test was previously green only because of the defect this task fixes - a pre-existing fault newly exposed rather than introduced - repair it within this iteration instead of reverting, but only with differential evidence recorded in the journal that the task's change altered no previously-passing output; without that evidence, revert. Severity discipline: a finding exercised only by out-of-envelope input is Low at most; never file inside a Settled class unless its implementing code changed since settlement; the third finding sharing one root cause replaces instance patching with one structural task or one Proposed decision; envelope changes and audit escalations go under Proposed, and Proposed items never block convergence and are never worked without user approval. Backlog discipline: BACKLOG.md is a ledger, not a narrative; when a task completes, delete its line from BACKLOG.md and record one closing line in the journal entry; never write prose sections, run context, or DONE annotations into BACKLOG.md; add discovered subtasks as one-line items and replenish with a partial audit when fewer than 3 open tasks remain, unless the run is in closeout. Closeout: once a full fresh-evidence audit in this run has scored zero High and zero Medium in-envelope, the run stops auditing for the rest of the run - no replenishment and no further full audit, however many iterations of budget are left - and finishes by working or declining what is already on the ledger and then converging; say in that audit's journal entry that closeout has begun. This is what bounds a run on a project with a long tail of Low findings, where each drained ledger would otherwise trigger another audit that files another Low and the run never ends. It never suppresses a real defect: entering closeout requires an audit that just found no High and no Medium, a High or Medium noticed while executing a task is still filed and still worked, and the evaluator gate and the next run's fresh audit both still apply. Append a JOURNAL.md entry with the heading grammar ## iter i/N | run-id | date | task-id or AUDIT or RATCHET or WRAPUP or SALVAGE or ROTATION | status, where run-id is the first 8 characters of the session id followed by a hyphen and the HHMMSS of started_at from the loop state frontmatter, so two runs in one session are told apart, and status is one of done, blocked, audit, converged, salvage, rotation - SALVAGE entries take status salvage, ROTATION entries take status rotation - and body fields Task, Changed, Checkpoint, Verification, Learnings, Next, in that order; each iteration writes one primary entry, and SALVAGE and ROTATION entries are additional. If JOURNAL.md exceeds 500 lines, move all but the last 10 entries to the end of JOURNAL-archive.md, appending to whatever that file already holds and never overwriting it - the archive accumulates across every rotation and every run, and the stop hook rejects an archive whose entry count fell - and record the rotation as a ROTATION entry. Lessons: when a Learnings line states an operational rule future iterations must obey - a build quirk, a command that must or must not be used, a mistake made twice - also append that rule as one line under ## Lessons in PLAN.md, keeping that section brief and free of status or task state. Checkpoint: at the end of every iteration, when the project is a git repository, run git add -A then git commit -q with the message jeffy: iter i/N task-id status, then evaluate the stall check below, record the new commit hash as Checkpoint in the current entry - completing the entry, not rewriting it - together with the stall note when one is due, and commit that small bookkeeping edit with the message jeffy: iter i/N bookkeeping, so the next iteration starts with a clean tree and salvage does not misfire; if the commit fails, record Checkpoint: none with the reason and continue; never push and never create branches. Stall check: if this iteration changed no file other than PLAN.md, BACKLOG.md, JOURNAL.md, or JOURNAL-archive.md and no BACKLOG.md item changed state, say so in the journal entry; if the previous primary entry already says the same, that is a hard blocker. Change discipline: before changing shared or public code, read its callers and the tests that pin it, and state in the journal entry what contract the change preserves; when a change alters a public function's behavior, signature, or accepted inputs, the same iteration updates its documentation and flips the affected Surface inventory rows back to [ ] so the next audit re-sweeps them - a fix that leaves its own module contradicting its docs or its siblings is not done. Edit only the files the task requires plus PLAN.md, BACKLOG.md and JOURNAL.md, all inside the current project folder. Never rewrite past journal entries, never write secrets into state files, use hyphens not dashes in file content. On a hard blocker - a missing dependency, a decision only the user can make, or a second consecutive no-progress iteration - append a journal entry naming the exact blocker, delete .claude/jeffy-loop.local.md to end the loop, and close with the run report. Run report: whenever a turn ends the run - convergence, the final iteration, or a hard blocker - finish your reply to the user with a run report: iterations used and how they were spent, tasks closed this run with their severities, the Surface inventory position as rows swept of rows total, the files changed across the run via git diff --stat against the commit that preceded this run's first checkpoint when the project is a git repository, tasks still open or blocked with their reasons, Proposed items awaiting a decision, the final Verify status, and a pointer to JOURNAL.md and git log for the full record. Closing rule: the run is converged only when the ratchet verification above succeeded, or the Definition of done in PLAN.md is genuinely and verifiably true: a full fresh-evidence audit this run scored zero High and zero Medium in-envelope, the Surface inventory in PLAN.md lists no unswept row, zero open tasks remain in Now, Next, and Later - every filed finding, Low included, is either completed, moved to Declined with a genuine not-worth-fixing reason, or marked [b] with its reason, so no Low is silently left behind - the only commits since that clean audit are the completed fixes for tasks it filed plus loop state file edits, the Verify command is green this iteration, the independent evaluator returned PASS, and a Converged line with the full commit hash is appended under ## Converged in BACKLOG.md. Evaluator gate: on the Definition of done path only, never the ratchet, before appending the Converged line spawn exactly one fresh-context sub-agent as an adversarial reviewer with these instructions: assume the run's work is broken until proven otherwise and do not praise; read PLAN.md and BACKLOG.md at the project root; review the run's changes with git diff and git log against the commit that preceded this run's first jeffy checkpoint; re-run the Verify command and the acceptance checks of the tasks closed this run and report their real output; look for missed in-envelope High or Medium findings, especially in code this run touched; return PASS only if every check holds, otherwise REJECT with each reason as one line carrying a file and line, a failing command, or a reproduced behavior; the Operating envelope and the evidence rule bind the evaluator exactly as they bind the audit. On PASS record Evaluator: PASS with a one-line summary in the Verification field of the closing journal entry. On REJECT do not converge: file each substantiated reason as an ordinary backlog task at rubric severity, or under Proposed if it challenges the envelope, record the rejection in the journal entry, and continue iterating within the budget; at most 2 evaluator invocations per run, and a second REJECT is a hard blocker handled by the hard blocker rule with the remaining reasons named in the run report. If sub-agent spawning is unavailable in this session, record Evaluator: unavailable with the reason in the closing journal entry and the run report, then converge under the remaining conditions. To end the run, output the run report, then the exact phrase JEFFY CONVERGED wrapped in promise XML tags, and never write that tagged form in any other context, including the journal.
