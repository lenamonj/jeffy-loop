## REJECT reasons

1. Medium - scripts/validate.sh check P tests each document with `grep -qF -- "$p_want"`, which
   asks only whether the canonical clause appears somewhere in the file. A document may therefore
   state the bound derivation a second time, differently, and check P stays green. This is not a
   hypothetical layout: skills/jeffy/SKILL.md line 63 already ships a second statement of the same
   chain in the launcher's executable prose, "compute the bound as three times the measured
   seconds, floored at 240", beside the canonical clause at the end of the same paragraph.
   Reproduced two ways. One: appending to README.md a sentence resolving the bound as
   `verify_timeout_seconds`, else `Verify duration` x5 floored at 100s, else 100s leaves checks P,
   L, M, I, J, Jb, Jd, Je and N all green. Two: changing the hook's multiplier from 3 to 4 and
   updating the canonical clause in all three documents, while leaving SKILL.md's prose saying
   three, leaves check P green and printing the x4 clause in its own pass message while the
   launcher text tells the model to compute x3. That prose is not documentation about the engine,
   it is the instruction the launcher executes to write `verify_timeout_seconds` into the loop
   state file, so the drift it permits is behavioural and not cosmetic. This is the same defect M1
   fixed in check L, which used to read one site with head -n 1 and now compares every site
   located by an anchor; check P has no site locator and was left on presence alone. The severity
   is the run's own calibration, applied twice already in this run: a guard that would not fault
   is a Medium even while nothing published is wrong today. It is not covered by the Comparison
   discipline paragraph, which deliberately omits P from its every-site list, and not settled by
   either of that section's two Settled entries.

2. Low - the Method's class rule in PLAN.md requires "Record each closed or declined class as one
   line under Settled classes in BACKLOG.md". This run's M1 was filed and closed as a class fix
   under the three-strike rule, and its own iteration-1 entry states it is a different class from
   the one it sits next to; G1 continued that class across nine extraction sites. BACKLOG.md's
   Settled classes section carries exactly two bullets, both recording earlier runs' classes, and
   neither names the comparison-projection class. So the class boundary and enumeration are on
   record only in JOURNAL.md, and the Method's protection against re-filing instances, which is
   keyed to the Settled classes list, does not apply to it. The Definition of done requires every
   finding, Low included, closed or genuinely declined before a declaration.

  start". One sed remains that is not: scripts/validate.sh line 461, `sed 's/.*alt="//; s/"$//'`,
  which carries a leading greedy `.*`. It is safe as written, because it runs over grep -o output
  where each line is exactly one match and the alt value is `[^"]*` so it cannot itself contain
  another `alt="`. The sentence is imprecise about that one line rather than false about the
  behaviour, so it is recorded here and not filed.

  matching arm, which is exactly what the leftmost sed match reads, and prepending a different
