claim is per site, and PLAN.md states otherwise. Reason 3 is separate.

1. Medium - scripts/validate.sh checks J (line 393), Jb (line 454), Jd (lines 570-574) and K
   (line 4655) extract their markers with a sed whose leading `.*` is greedy, so each yields at
   most one value per line, not one per site. The M1 guards those lines carry therefore compare a
   projection again: a second, disagreeing site on the same line as the first is invisible to them.
   This is not a hypothetical layout - README.md already carries two count:converged markers on one
   line, and changing the first of that pair to 99 leaves both check J and check Jd green
   (reproduced; only check N, which uses grep -o and predates this run, faults). With the same
   move, a README stating a wrong pie alt description first passes check Jb green, and a README
   published as held to 999 behavioural checks and to 203 behavioural checks passes check K green
   in a maintainer-shaped tree where its derivation arm actually runs. Nothing else reads the
   count:checks marker or the alt attribute, so for those two there is no second reader to save the
   suite. The severity is the run's own: this is the class M1 was filed to close, filed then as a
   Medium on the reasoning that a guard which would not fault is a Medium even while nothing
   published is wrong today, and that reasoning applies unchanged here.

2. Medium - PLAN.md's "Derived and settled claims" section, Comparison discipline paragraph, states
   that checks I, J, Jb, Jd, K, L, M and N "each read every site or marker of their claim rather
   than the first". Reason 1 shows that is false for J, Jb, Jd and K on the marker layout the
   shipped README already uses, so the governance file that exists to record what each derivation
   compares now records something the reproductions contradict. Misleading documentation of exactly
   the kind this section was written to prevent.

3. Low - scripts/validate.sh line 900, `for o_f in $o_files`, word-splits the newline-delimited path

   enumeration L1's acceptance check used, `grep -c 'for [a-z_]* in \$(' scripts/validate.sh`,
