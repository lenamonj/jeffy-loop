# Jeffy eval: valyala/fasthttp

**Target**: [valyala/fasthttp](https://github.com/valyala/fasthttp) (23,422 stars, verified via `gh api repos/valyala/fasthttp --jq '.stargazers_count'` on 2026-07-30) at `f83ac8c3560feccaa017ba86dd9b95ad004790f2`, which is **exactly the `v1.73.0` release tag** of 2026-07-27, not a random master commit. Go, in a local clone; the loop's work was never pushed anywhere. fasthttp is the high-performance HTTP server and client library used as the transport under Fiber and a large part of the Go web ecosystem, and it is the **largest target in this set**: 160 Go source files, four of them over 80KB.

**This is a full `/jeffy` loop run that reached machine-checked convergence.** Seven runs, 58 iterations: **31 findings filed and closed (6 High, 12 Medium, 13 Low)** across a diff of **46 files, +4,112/-269**, of which 3,251 insertions are tests. The suite grew by **57 new test functions** to **1,311 passing**. Converged at `892d987b651205572bba023690f89dd323118001` on 2026-07-30: empty ledger, **all 40 surface-inventory rows swept**, the verify command (`go test ./...`) re-run fresh for this receipt at exit 0 across all 9 packages, and the adversarial evaluator's PASS on record from a fresh-context sub-agent that re-ran the gates itself.

Because the baseline is a release tag rather than an unreleased branch, **every finding here is in code that shipped to users.**

## What the loop found

- **BC-4 (High, security)** - `appendBodyFixedSize` sized its allocation directly from the peer's declared `Content-Length`, so a default-configured `Client` could be killed by an honest-looking response header. A remote party choosing the number that sizes your allocation is the whole defect; no malformed input required.
- **BC-2 (High, security)** - `parseUintBuf`'s overflow guard tested the product against the accumulator, which misses wrapping that lands back above it, so `ParseUint` disagreed with `strconv` on values that overflow. Content-Length parsing sits on top of it. Closed with `TestParseUintMatchesStrconv`, a differential comparison against `strconv` over hand-picked inputs plus a generated search of 19-to-21-digit values, so the two implementations cannot silently diverge again.
- **FS-1 (High, security)** - the FS handler accepted Windows-reserved name forms on every path segment, not just the last. Fixed class-complete at one boundary (`hasWindowsReservedPathName`), covering `:` outside a leading drive letter and any component ending in `.` or a space, checked per component.
- **FS-4 (High, correctness)** - the generated directory index linked to files it could not then serve, because every `href` was built from an already-decoded path and re-decoded on the way back in. The index advertised its own broken links.
- **ZSTD-1 (High, security)** - the flate and zstd compression level scales were never reconciled, so a documented level could panic the process or be silently discarded. Closed by driving every documented `CompressHandlerLevel` value through a real request with `Accept-Encoding: zstd` and decoding the result, plus every zstd constant and five out-of-range integers through `AppendZstdBytesLevel`.
- **MPART-1 (Medium raised to High during execution)** - the documented multipart body-size limits did not bind at all. Filed Medium by an audit and raised on evidence found while executing it, which is the rubric working in the direction that costs more work rather than less. Closed class-complete at the two boundaries that decide whether a multipart body is parsed.
- **Twelve Medium findings**, including `Set` replacing only the first occurrence of a duplicated header key so a peer's duplicate survived into the serialized bytes (HDR-1, settled class-complete at `setArg`, the single boundary all seven call sites go through); `Peek`/`PeekAll` concatenating every `Set-Cookie` into one value so a caller enumerating cookies got one wrong string (HDR-2); `..` not resolving against backslashes on Windows so `URI.Path()` broke its documented promise (URI-1); the forbidden-trailer filter blocking only part of the categories its own doc comment declares (TRAIL-1); the proxy dialer parsing a CONNECT response through a throwaway `bufio.Reader` and returning the bare connection, discarding anything already buffered (PROXY-1); and `fasthttpadaptor` hardcoding `ProtoMinor = 1` so an HTTP/1.0 request reached the wrapped `net/http` handler claiming to be 1.1, which is exactly what those handlers branch on to decide framing (ADAPT-1).
- **Thirteen Low findings** covering RFC conformance (a 416 with no `Content-Range`, leading zeros accepted in an IPv4 octet, `Accept-Encoding` matched as a substring so `GZIP` in a token was mistaken for the coding), error-handling shape (a `..` guard answering 500 where its two sibling guards answer 4xx), and documentation that contradicted the code.

## How it converged

The `git log -S` discipline is worth naming because it produced **opposite verdicts on consecutive iterations**. Facing a finding that two sibling code paths contradicted each other, the loop checked the history of the test pinning the behaviour before writing a fix. In one iteration that revealed a deliberate upstream scope decision and sent the finding to Proposed unexecuted; two iterations later the same command revealed an incidental choice with no defence in its commit message, and cleared the fix. Neither verdict was predictable from reading the test alone.

The first convergence declaration was **rejected by the Stop hook**, and the reason is instructive: PLAN.md's `Command:` line carried markdown backticks, and the hook executes that line verbatim under `bash -c`. The backticks became command substitution, so the suite ran green and then its own `ok github.com/valyala/fasthttp` output was executed as a command. `ok` is not a command, which is exactly exit 127. The next iteration reproduced the failure through the hook's own `awk` extraction both ways, removed the backticks, wrote the rule into PLAN.md's Lessons, and re-declared. No Go source was involved. That is why `## Converged` carries two lines.

## Honest caveats

- **Two inventory rows could not be swept on the host machine.** `ListenAndServeUNIX`, and the `reuseport`/`tcplisten` Unix path, do not compile on Windows. The run raised this as a hard blocker rather than scoring around it. It was resolved by **real execution on a Linux kernel via WSL**, not by inference or CI delegation: a unix socket served end to end at permission modes 0600 and 0666 with the created socket's mode bits asserted equal to the argument at both, two `reuseport` listeners bound the same port simultaneously and the kernel spread 40 connections exactly 20/20 across them, and `tcplisten`'s own tests executed for the first time in this project's audit history. The Windows working tree was untouched by that sweep.
- **Dependency hygiene rests on version currency, not a scan.** `govulncheck` was unavailable offline, and the run states this rather than implying a clean scan. The six direct dependencies were reviewed as small, widely adopted and recent.
- **One finding was declined on a delegated judgement call, not a purely technical one.** CLI-1 (a 301 or 302 redirect of a POST keeps forwarding the body after switching the method to GET, unlike the 303 branch and unlike `net/http`) sat under Proposed for several runs because executing it would overturn a deliberate upstream decision. The user delegated the call, and it was declined: upstream chose the behaviour in `cb4dc24` / PR #2265, pinned it in `TestClientFollowRedirects`, changing it is a silent breaking change with no driving bug report, and the cross-host exposure that would justify overriding upstream is already mitigated by `stripSensitiveHeadersOnRedirect`.
- **One pre-existing upstream test was renamed and its status expectation changed.** `TestFSServeRejectsBackslashDotDotSegments` became `TestFSServeNeutralizesBackslashDotDotSegments`. This is the change a skeptic should grep for, so here is the whole of it: the `TOP_SECRET` no-disclosure assertion is **byte-identical**, the expected status moved from 500 to 404 because URI-1 neutralizes the traversal at the URI layer before the FS handler's guard can fire, and a **stronger** assertion was added checking the resolved path holds no `..` segment at all. The test was tightened, not softened. It is the only test function in the diff whose name changed, and no upstream test was deleted.
- **Six of the seven runs did the excavation; the seventh only closed it out.** Runs one through five, on Opus, filed and fixed the substantial majority of the 31 findings and swept most of the inventory. The final two runs completed the last inventory rows, ran the clean closing audit and handled the convergence path. The converging session ran on `claude-fable-5`, verified from its transcript. Attributing the result to one model would be wrong.
- **One run was cancelled after two iterations** and contributed an audit and a journal rotation, nothing more. It is counted in the 58.

**Status**: the work lives in this eval's `fixes.patch` (46 files, +4,112/-269, applies to pristine `f83ac8c3`) and `journal.md` (all 58 entries across the seven runs, as written, including the rotated archive).

**Upstream**: BC-2 is filed as [valyala/fasthttp#2343](https://github.com/valyala/fasthttp/pull/2343), 2 files, +76/-4, opened against a master still sitting at the audited commit. It was chosen over the other thirty findings on one criterion: its test asserts only that `ParseUint` agrees with `strconv.ParseInt` about which decimal strings are in range, so a maintainer can accept it without accepting any judgement of ours about desired behaviour. Every other candidate asks him to agree with us about intent. The reproduction in the PR body was executed against a clean clone of upstream master, not inherited from this run's journal: `Content-Length: 21000000000000000000` is accepted and parsed as `2553255926290448384`. The narrow band is why it survived - `9223372036854775808` and `99999999999999999999` are both already rejected correctly, and the defect only appears where `10*v` wraps back above `v`.

Deliberately not submitted: BC-4 invites the reply that `MaxResponseBodySize` exists for that, which is a design conversation rather than a bugfix; FS-1 is Windows-only and lands on top of #2335 and #2327, both merged the week of the audit; HDR-1 and HDR-2 change the behaviour of public accessors and invite a breaking-change objection; and URI-1 would change the expected status of a test upstream merged five days before this run. ADAPT-1 is the natural second PR once the first lands.

One piece of upstream context worth recording, because it inverted an assumption. PR [#1698](https://github.com/valyala/fasthttp/pull/1698), "fix: Path Traversal Attacks on Windows", has been open since January 2024, which reads as a maintainer who resists that class. It is not. The PR has an empty body, zero comments, and commented-out code left in the diff, while the same maintainer merged two Windows FS security fixes in the week of this audit, in two days and eleven days. The class was never the obstacle.
